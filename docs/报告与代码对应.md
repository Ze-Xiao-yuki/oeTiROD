# 报告与代码对应

对应当前《结项报告_逐项校正版.docx》，不修改报告正文、封面或目录。

| 报告内容 | 代码位置 | 当前处理 |
|---|---|---|
| 2.2 双来源数据、5.1任务序列 | `configs/tirod.yml`、`self_collected.yml`、`data/manifest.py` | 分别描述公开与自采任务；从COCO读取类别与数量，拒绝混乱映射 |
| 2.4系统架构、2.5接口 | `train_eval/runtime.py`、`run.py` | 数据、模型、策略、输出采用公共入口与元数据对象 |
| 3.2短期记忆 | `memory/hierarchy.py` | 有界队列保存图像索引、任务、场景、时间和标注状态 |
| 3.2长期记忆 | `memory/hierarchy.py`、`methods/project.py` | 可靠标注才能回放，按场景/类别覆盖筛选，按编码器版本比较描述特征 |
| 3.2永久记忆 | `HierarchicalMemory.archive` | 保存发布模型、类别表、样本索引及SHA256；拒绝同版本覆盖 |
| 3.2紧凑特征 | `memory/features.py` | 64维检索描述与检测用空间特征分别处理 |
| 3.3专家与路由 | `model/experts.py` | 共享ShuffleNetV2和GhostPAN，专家检测头独立；亮度、对比度及共享特征摘要输入路由 |
| 3.3专家更新 | `SharedExpertDetector.select_training_expert` | 后续任务冻结共享部分和无关专家，并冻结对应BN运行状态 |
| 3.4微睡眠维护 | `maintenance/microsleep.py` | 有符号软阈值；排除偏置、归一化参数及受保护前缀；验证下降、超预算或异常时回滚 |
| 3.5连续更新 | `train_eval/engine.py` | 当前/历史样本共同训练，固定验证选模型，归档后评估历史任务 |
| 4.1十方法实践 | `methods/` | 每种方法独立文件，公共数据与训练流程统一 |
| 4.3推理和记忆维护 | `tools/infer.py`、`methods/project.py` | 推理输出含模型和专家版本；训练任务完成后按候选预算更新记忆 |
| 4.4训练、评估、演示 | `train_eval/metrics.py`、`visualization/`、`tools/infer.py` | 完整下三角矩阵，平均性能、保留符号的遗忘量，视频演示输出 |
| 4.5 PC和边缘推理 | `--device`参数及公共推理入口 | 支持在配置好PyTorch的PC/NX上运行；未宣称已做TensorRT优化或设备性能验收 |

实现范围：三重记忆已接入项目配置的任务回放与归档；实时推理当前输出带版本的JSONL，不自动把无标注检测结果当作监督数据。持续视频采集、人工标注工具、云端上传、自动服务切换与空间特征缓存格式并未附加实现。

原配置输入尺寸为640×640，项目保留该默认值。若实验选用报告中讨论的416×416，应同时修改`configs/nanodet.yml`中的训练和验证尺寸，并重新运行；不把不同输入尺寸产生的结果混成同一实验。
